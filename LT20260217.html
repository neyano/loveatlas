技術用語解説：サーバー環境

Apache（アパッチ）とは？

Webサーバーソフトウェア。ブラウザからのリクエストを受け取り、Webページを配信する役割。世界で最も使われているWebサーバーの1つ。

MariaDB（マリアDB）とは？

データベース管理システム。MySQLから派生したオープンソースのデータベース。
MySQLとの違い：元々は同じだったが、開発元が異なる。機能はほぼ同じで互換性が高い。MariaDBの方が新機能の追加が早い傾向。XAMPPには最初からMariaDBが入っている。

Leaflet + OpenStreetMap とは？

Leaflet：地図を表示するためのJavaScriptライブラリ（プログラムの部品集）
OpenStreetMap：誰でも自由に使える世界地図データ（Wikipediaの地図版）

主要機能（1/2）

地図機能

  • 操作できる地図：ドラッグで移動、ピンチで拡大縮小できる動的な地図
  • ピン表示：作品タイプ別に色分け（映画=青、アニメ=赤...）
  • クラスタリング：近い場所のピンをまとめて表示（後述）
  • ポップアップ：ピンをクリックするとセリフ概要が表示される

投稿機能

  • セリフ投稿：作品・場所・キャラクターを紐付け
  • 自由な投稿：アニメ・映画に限らず、名言や思い出の写真も投稿可能
  • 承認フロー：管理者が確認後に地図に公開（後述）

用語解説：地図機能

インタラクティブ地図とは？

ユーザーが操作できる地図のこと。
できること：ドラッグで移動、ピンチ/ホイールで拡大縮小、ピンをクリックして情報表示
対義語：静的な画像の地図（操作できない）

承認フローとは？

投稿されたセリフを管理者がチェックしてから公開する仕組み。
流れ：①ユーザーが投稿 → ②管理者が確認 → ③承認されたら地図上に表示
目的：スパムや不適切コンテンツの防止

クラスタリングとは？

近くにある複数のピン（マーカー）を1つにまとめて表示する機能。
例：東京に100個のピンがある場合、遠くから見ると「100」という数字の丸印1つで表示。拡大すると個別のピンに分かれる。
メリット：地図が見やすくなり、動作が軽くなる

主要機能（2/2）

インタラクション/ソーシャル

  • いいね：ボタンを押すたびに追加・解除が切り替わる
  • お気に入り：気に入ったセリフを保存
  • 訪問記録：日付・メモ・評価・写真を記録

探索機能

  • 横断検索：セリフ・作品・場所を一度に検索（後述）
  • Explore：人気・新着セリフの一覧
  • タグ機能：タグ別一覧表示

用語解説：探索機能

横断検索とは？

複数のカテゴリを一度に検索すること。
例：「東京」と検索すると、セリフ・作品・場所の全てから「東京」を含むものを表示
通常の検索：セリフだけ、作品だけ、など1カテゴリずつ検索

バウンディングボックス取得とは？

今画面に表示されている地図の範囲（北端・南端・東端・西端）を取得すること。
目的：表示範囲内のデータだけを取得することで高速化
例：東京を表示中なら東京周辺のセリフだけ取得。大阪のデータは取得しない

300msデバウンスとは？

地図を動かしてから0.3秒待ってからデータを取得する仕組み。
理由：ドラッグ中に何度もデータ取得すると重くなるため、動きが止まってから取得する

データ構造

users ──1:N──> quotes      (1人のユーザーが複数のセリフを投稿)
works ──1:N──> quotes      (1つの作品に複数のセリフが紐づく)
locations ──1:N──> quotes  (1つの場所に複数のセリフが紐づく)
users ──1:N──> favorites   (1人のユーザーが複数をお気に入り登録)
users ──1:N──> visits      (1人のユーザーが複数の場所を訪問記録)
users ──1:N──> votes       (1人のユーザーが複数にいいね)
quotes <──N:M──> tags      (セリフとタグは多対多の関係)

用語解説：データ関係図の見方

1:N（1対多）とは？

意味：1つに対して複数が紐づく関係
例：users ──1:N──> quotes
→ 1人のユーザーは複数のセリフを投稿できる
→ 1つのセリフは1人のユーザーにのみ属する

N:M（多対多）とは？

意味：どちらも複数が紐づく関係
例：quotes <──N:M──> tags
→ 1つのセリフに複数のタグを付けられる（例：「感動」「恋愛」「青春」）
→ 1つのタグは複数のセリフに使われる（例：「感動」タグは100個のセリフに使用）

矢印の向きの意味

users ──> quotes：ユーザーからセリフへの矢印 = ユーザーがセリフを「所有」する
quotes <──> tags：双方向の矢印 = お互いに複数紐づける

用語解説：MVPとは？

MVP（Minimum Viable Product）

意味：必要最小限の機能を持った製品
日本語訳：実用最小限の製品
目的：全機能を作る前に、最小限の機能でリリースしてユーザーの反応を見る
例：LoveAtlasのMVPは「地図表示」「セリフ投稿」「検索」など基本機能のみ。AR機能や多言語対応は将来の拡張

MVPリリース時とは？

最初に公開する時点のこと。この時点では基本機能のみ実装されており、将来的に機能を追加していく

セキュリティ対策

  • 認証システム：ユーザーのパスワードを暗号化して保存
  • 不正アクセス対策：ログイン試行回数を制限（1分間に5回まで）
  • データベース攻撃対策：悪意のあるSQL文による攻撃を防止
  • スクリプト攻撃対策：悪意のあるJavaScriptの実行を防止
  • なりすまし対策：他人のふりをした不正な操作を防止
  • API利用制限：短時間の大量アクセスを制限（1分間に60回まで）

セキュリティ用語解説

Sanctum + bcrypt ハッシュ（パスワード暗号化）

パスワードを暗号化して保存する仕組み。万が一データベースが盗まれても、元のパスワードは分からない。bcryptは一方向暗号化（元に戻せない）

SQLインジェクション対策（Eloquent ORM）

データベースへの不正な命令文を防ぐ。攻撃例：ログインフォームに「' OR '1'='1」と入力して全データを盗む → Eloquent ORMが自動で無害化

XSS対策（クロスサイトスクリプティング）

悪意のあるJavaScriptを埋め込まれる攻撃を防ぐ。
攻撃例：コメント欄に「<script>悪意のあるコード</script>」 → Bladeが自動でエスケープ（無害化）

CSRF対策（クロスサイトリクエストフォージェリ）

他人のふりをして不正な操作をする攻撃を防ぐ。攻撃例：罠サイトを踏むと勝手に投稿される → トークン（合言葉）で本人確認

レート制限

短時間の大量アクセスを制限。理由：パスワード総当たり攻撃やサーバー負荷攻撃を防ぐ。例：ログイン5回/分、API60回/分

5人並行開発

グループA 地図・位置情報（Leaflet, クラスタリング）
グループB 認証・プロフィール（Sanctum）
